# Build a Personal Website

## 明确目标

在开始实现前，确认：

- 网站的主要访客与使用场景。
- 希望传达的个人定位。
- 访客浏览后应采取的主要行动。
- 能够证明个人能力的经历、项目和作品。
- 已有代码、设计、文案、素材与部署环境。

缺少会改变页面结构或实现方案的重要信息时，提出少量关键问题。可以安全推断时，明确说明假设并继续。

## 检查现有项目

如果存在代码仓库：

1. 检查项目结构、技术栈、运行命令和部署方式。
2. 检查已有页面、组件、样式、素材和未提交修改。
3. 保持现有代码风格，只修改任务需要的内容。
4. 验证构建方式和公共资源路径，不覆盖用户工作。

如果没有现有项目，选择满足需求的最简单实现方式，不引入没有明确价值的依赖。

## 规划内容

先建立内容和证据，再决定视觉形式。整理内容或编写项目案例时，读取 [content-and-case-studies.md](references/content-and-case-studies.md)。

根据实际需要组织以下模块：

1. 首屏定位与主要行动按钮。
2. 个人简介、背景和关注方向。
3. 能证明能力的代表项目。
4. 能力、服务或工作方法。
5. 联系方式与下一步行动。

让每个页面区块承担一个主要信息任务。使用具体案例证明能力，减少空泛的自我评价。

## 建立视觉规则

先确定阅读顺序和信息层级，再统一：

- 主色、辅助色和背景色。
- 标题、正文和辅助文字。
- 内容宽度、间距、圆角和边框。
- 图片比例、卡片和按钮状态。
- 动效速度、缓动和出现顺序。

让视觉方向符合个人定位和内容主题。优先复用少量稳定规则，避免未经要求的模板感、过度装饰和单次使用的复杂设计系统。

## 实现页面

- 使用语义化页面结构。
- 只为重复出现的界面模式提取组件。
- 保证手机、平板和桌面端可以正常阅读。
- 为交互元素提供悬停、聚焦、按下和禁用状态。
- 保证键盘可以访问主要导航和操作。
- 为有意义的图片提供准确替代文本。
- 明确区分真实功能、演示交互和占位内容。
- 不擅自增加后台、账户、数据库或支付系统。

## 使用动效与媒体

只在动效能建立阅读顺序、引导注意力、表达状态或提供反馈时添加。支持 `prefers-reduced-motion`，确保关闭动效后内容仍然完整可用。

处理媒体时：

- 设置图片尺寸，减少布局跳动。
- 压缩图片、视频和字体。
- 延迟加载非首屏媒体。
- 按需加载大型案例和交互模块。
- 在悬停或键盘聚焦等明确意图出现时预加载。
- 为视频提供封面和移动端降级方案。

## 验证与交付

交付前读取并执行 [quality-checklist.md](references/quality-checklist.md)。实际打开页面检查关键尺寸和交互，不能只依赖代码审查。

交付时简要说明：

- 完成的页面和功能。
- 内容结构与视觉方向。
- 运行、构建和部署方式。
- 已执行的验证。
- 尚未替换的占位内容。
- 素材、部署或外部服务限制。

## 工作边界

- 不虚构个人资料、项目成果、客户、数据或联系方式。
- 不把演示表单描述成真实消息发送功能。
- 不重构与当前目标无关的代码。
- 不覆盖或夹带用户已有修改。
- 不为了展示技术而牺牲内容清晰度。
